UNITE-ONE V1.9.0 排位模式更新
================================

檔案
- index.html：更新後的主遊戲頁面
- rank-assets/：段位徽章與「大集結巔峰」圖示，請整個資料夾一起上傳

部署方式
1. 解壓縮本 ZIP。
2. 將 index.html 與 rank-assets 資料夾一起放到 GitHub Pages 網站根目錄。
3. 覆蓋原本的 index.html，並新增/更新 rank-assets 資料夾內的圖片。
4. 部署完成後重新整理網站；桌面瀏覽器可使用 Ctrl+F5。

排位規則
- 單人模式，固定地獄難度、完整題庫、不可使用提示、最多 4 次猜測。
- 目標：在 1、3、5 分鐘內猜中 1 隻寶可夢。
- 三種時間模式的段位、積分、連勝與排行榜完全獨立。
- 猜測獎勵：第 1 次 +30；第 2～3 次 +25；第 4 次 +20。
- 挑戰失敗 -15；積分最低為 0。
- 連勝獎勵：3 連勝 +5、5 連勝 +10、10 連勝 +20、15 連勝 +30、20 連勝 +40。每達成一次里程碑就發放一次；失敗重置當前連勝，最高連勝保留。
- 高級 III/II/I：0–299（每階 100 分）。
- 菁英 III/II/I：300–599（每階 100 分）。
- 專家 V/IV/III/II/I：600–1099（每階 100 分）。
- 達到 1100 分進入大師，大師積分從 0 開始；大師失敗扣分但最低維持 0，不會降回專家。
- 大師累積到 500 分進入傳奇；傳奇積分繼續累積，低於 500 分回到大師並重置大師積分為 0。
- 傳奇積分排行榜前 100 名取得「大集結巔峰」；跌出前 100 名回到傳奇。
- 排行榜排序：積分高者優先；同分依最高連勝、累積勝場、較早達到目前積分的時間排序。

Firebase Realtime Database
- 未登入時，排位進度保存在目前瀏覽器的 localStorage。
- 登入或以訪客帳號登入後，會將該帳號的排位資料同步到 Firebase，並讀取跨玩家排行榜。
- 排行榜資料路徑：rankLeaderboard/{m1|m3|m5}/{uid}
- 若排行榜顯示 PERMISSION_DENIED，請將以下片段合併到 Firebase Realtime Database 現有的 rules 物件內。不要覆蓋你原本的 users、roomPublic、roomSecrets 等規則：

"rankLeaderboard": {
  "$mode": {
    ".read": "auth != null",
    "$uid": {
      ".write": "auth != null && auth.uid === $uid"
    }
  }
}

注意
- 目前排行榜由前端計算與提交，Firebase 規則限制登入者只能寫入自己的 UID 節點，但並沒有伺服器端驗證每次猜測與積分，因此不是防作弊排行榜。若要正式競技級防作弊，需要另外建立伺服器端驗證流程。
- Firebase 雲端同步、多人實際連線與 GitHub Pages 上線結果，仍需在你的 Firebase/GitHub 環境中測試。
